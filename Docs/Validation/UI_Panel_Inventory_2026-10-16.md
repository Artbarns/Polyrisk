# Inventaire de recette UI — PolyRisk — 16 octobre 2026

Cette matrice recense les écrans UXML actuels, les preuves de recette présentes dans le dépôt et les contrôles qui restent nécessaires. Elle distingue le rendu déjà exercé des contrôles physiques ou de comparaison au mockup ; une compilation seule ne vaut pas recette visuelle.

Le contrôle Unity Editor `UIAssetRegression` charge puis clone 17 écrans/composants UXML et vérifie leurs éléments nommés/actionnables : **194 assertions PASS** sous Unity 2022.3.62f3. Cette suite est appelée avant le build dans `EconomyBatchValidation.BuildVerifiedWebGLPreview`. Elle prévient les templates ou actions manquants, mais ne calcule pas la mise en page, n’exécute pas les callbacks et ne certifie pas le rendu.

Le 16 octobre, `EconomyBatchValidation.RunAllEditorRegressions` a rejoué les trois suites sans lancer le linker WebGL : Économie **114/114**, Mécaniques **140/140**, UI **194/194**, processus Unity batch code 0. Total : **448 assertions**. `BuildVerifiedWebGLPreview` utilise ce même groupe avant de compiler le joueur.

## Parcours groupés pour terminer plus vite sans perdre de couverture

Une seule build Release et une même matrice de viewports peuvent couvrir plusieurs panneaux : (1) accueil/lobby, (2) tour et inspector, (3) sélection Marketplace + sanctions, (4) notification + offre + revue/spectateur, (5) Venture, (6) faillite, (7) victoire, (8) menu Quitter. Pour les écrans de fin et la carte, un état de test déterministe réduit les manipulations, mais chaque état doit être rendu dans Unity/WebGL et capturé ; les tests Editor actuels ne prouvent pas son apparence.

## Limites des références

L’audit de dépôt consulté contient des captures d’anciens builds, mais aucun fichier de mockup cible ni les deux captures de référence du message initial n’est identifié dans l’espace de travail. La comparaison fidèle reste donc à faire dès que ces visuels sont accessibles. Ce rapport n’autorise aucun changement de règle, de donnée économique ni de mécanique.
